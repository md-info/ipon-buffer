# Merchant rewards prototype

Open Rewards & partners from the Buffer header. The seeded fictional grocery campaign awards PHP 10 cashback for a simulated purchase of at least PHP 100, once per demo session, subject to a PHP 200 total reward budget and a 30-day expiry set on first installation. A purchase deducts its full value from the everyday mock wallet. Cashback is held separately until the user confirms moving it to the buffer. All amounts use integer centavos. Purchase/redeem retries are idempotent; purchases, budget deductions and reward credits commit in one transaction. Balance changes invalidate prior savings recommendations.

Demo partner tools create seven-day campaigns with merchant name, eligible-purchase description, minimum spend, fixed cashback and capped budget. Remaining budget is visible. Own-campaign purchases are rejected; use another synthetic session for evaluation. This is not verified merchant onboarding. Campaign funding is an explicitly simulated allocation, not money collected from a partner. No live settlement, merchant contracts or real cashback exists. Purchase eligibility is self-entered for the demo, not SKU- or receipt-verified. No refund/reversal workflow is implemented.

Community points remain noncash, nonredeemable reputation. Merchant cashback is separate. This version implements cashback-to-buffer, not a redeemable points catalog or checkout discount codes. A production wallet adapter must verify merchant identity, settled transaction IDs and eligibility; handle refunds, signed webhooks, fraud, reconciliation, expiry and real reward funding. Never expose the synthetic purchase endpoint as real payment confirmation. Existing host transport and navigation interfaces remain in docs/NEARBY_INTEGRATION.md; rewards endpoints are additional demo API routes, not native GCash integration.

Business hypothesis: integration/licensing revenue for Ipon and optional merchant campaign tooling revenue for the wallet provider. Measure incremental eligible merchant purchases/retention against reward and operation costs. Measure user financial outcomes separately. No conversion uplift or partner adoption is claimed.
